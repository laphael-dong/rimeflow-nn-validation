# rimeflow-yolov8n

YOLOv8n inference for the **rimeflow** family — pure-Rust postprocess, a
cross-target wgpu preprocess pipeline, and both an `onnxruntime-web` (WebGPU)
wasm bridge and a `pykeio/ort` (CoreML / DirectML / CUDA / TensorRT / NNAPI /
QNN / OpenVINO) native backend, all sharing one WGSL shader and one letterbox
math.

This crate implements the operator layer of the RimeCut NN development template
(revision r4). See `rimecut-feature-dev-onnx-development-rules.md` for the full
design context — including why the wasm side exposes **two** input APIs and how
the transition ends.

## Layout

```
rimeflow-yolov8n/
├── Cargo.toml            features: native / native-<ep> / model-embedded
├── build.rs              injects preprocess.wgsl into the inline_js payload
├── shaders/
│   └── preprocess.wgsl   SINGLE-SOURCE WGSL (letterbox + RGBA→NCHW normalize)
├── models/
│   └── yolov8n.onnx      ~13 MB, Ultralytics export
└── src/
    ├── lib.rs            module wiring + MODEL_URL / MODEL_BYTES / INPUT_SHAPE
    ├── preprocess.rs     LetterboxParams + PreprocessUniform + PreprocessPipeline
    ├── postprocess.rs    Detection + decode_yolo_output + nms  (pure Rust)
    ├── ort_bridge.rs     wasm32: extern block generated by build.rs
    │                              main-line: ort_run_gpu_buffer + ort_run_cpu_slice
    │                              transition: ort_detect(canvas)
    ├── ort_bridge_template.js    inline_js template (build-time input)
    └── native_ort.rs     non-wasm + feature="native":
                          NativeOrtBackend via pykeio/ort v2 + EP fan-out
```

## What each layer owns

- `postprocess.rs` — pure Rust, no external deps, no target gating. Decodes the
  raw model tensor `[1, 84, 8400]` into `Vec<Detection>` with letterbox inverse
  mapping, runs greedy NMS. Used by every consumer.
- `preprocess.rs` — the shared wgpu compute pipeline builder. Consumers create
  one `PreprocessPipeline` per session and call `dispatch(scene_view, letterbox)`
  per frame. Same code path on wasm (WebGPU backend) and native (Metal / Dx12 /
  Vulkan / GL); the only per-EP variance is the buffer usage mask chosen at
  construction time.
- `ort_bridge.rs` — wasm-only. Contains a tiny Rust wrapper plus the extern
  block generated by `build.rs` from `ort_bridge_template.js` (with the WGSL
  substituted in). No hand-written duplicate of the shader lives here.
- `native_ort.rs` — non-wasm, feature-gated. Wraps `pykeio/ort` with the r4 §4.4
  EP order (CoreML/DirectML first per platform, TensorRT/CUDA for NVIDIA opt-in,
  NNAPI/QNN on Android, CPU fallback always last). Currently drives inference
  by CPU-readback of the wgpu buffer; per-EP zero-copy handoffs land in a
  follow-up without touching the public API.

## The wasm dual-API design

There are **two** input APIs on the wasm side; consumers pick per their frame
source.

| API                                     | Frame source          | Consumer               | Zero-copy | Status     |
|-----------------------------------------|-----------------------|------------------------|-----------|------------|
| `ort_run_gpu_buffer(gpu_buffer, dims)`  | `web_sys::GpuBuffer`  | RimeCut main-line      | Tier A ✅ | Primary    |
| `ort_run_cpu_slice(nchw, dims)`         | `Float32Array` (host) | main-line fallback     | Tier C    | Fallback   |
| `ort_detect(canvas)`                    | `HTMLCanvasElement`   | open_quartz, debug     | Tier A / C dual sub-path | Transition |

Both paths execute the **same** WGSL preprocess (built from
`shaders/preprocess.wgsl`) and the **same** letterbox math (Rust
`LetterboxParams::compute` mirrored by JS `_computeLetterbox` in the template
— unit tests in `preprocess.rs` pin the reference values).

`ort_detect(canvas)` internally routes to one of two sub-paths at call time:

- **GPU sub-path (Tier A):** enabled when `_deviceShared === true` and a
  startup `fromGpuBuffer` end-to-end probe returned nonzero output. The path
  runs `createImageBitmap(canvas, { resizeWidth, resizeHeight })` for GPU-side
  downscale, `copyExternalImageToTexture` to hand it to a persistent input
  texture, the same WGSL preprocess as the main-line path, then
  `ort.Tensor.fromGpuBuffer` on the same shared `GPUDevice`. Steady-state at
  4096×3072 on an RTX 3050 Ti Ampere: ~30 ms `session.run`, ~40-50 ms
  end-to-end.
- **CPU sub-path (Tier C):** WebGL2 or WebGPU-without-device-sharing hosts.
  `OffscreenCanvas.drawImage` + `getImageData` + `new ort.Tensor('float32')`
  + WebGPU / WASM EP inference. Steady-state ~50-70 ms.

**Canvas race handling:** WebGPU-backed canvases (the RimeCut compositor
output) invalidate their current-texture handle at the end of each
animation-frame task. If `ort_detect` is called between the compositor's
`submit` and its `present`, `copyExternalImageToTexture` fires a validation
error via `pushErrorScope`. In that case `ort_detect` returns **`null`**
(instead of a result dict) and the caller must treat that as "drop this
detection cycle." This is the only allowed non-dict return value; the
RimeCut wasm binding uses it to advance the tracker's Kalman filter without
running IoU association.

The main-line RimeCut app **must not** call `ort_detect` — CI enforces this.
Once open_quartz gains a wgpu frame source, `ort_detect` and the JS-side
canvas compute pipeline are deleted in one shot.

## Web usage — main-line

```rust
use rimeflow_yolov8n::{
    ort_bridge,
    preprocess::{LetterboxParams, PreprocessPipeline},
    postprocess::{decode_yolo_output, nms},
    DST_SIZE, MODEL_URL,
};

// One-time init (before wgpu Instance/Adapter/Device init):
ort_bridge::capture_webgpu_device();
// … later, after wgpu Device is ready …
ort_bridge::ort_init(MODEL_URL).await?;

// Per session:
let pipeline = PreprocessPipeline::new(
    &device,
    DST_SIZE,
    PreprocessPipeline::default_buffer_usage(),
);

// Per frame — scene_view is a wgpu::TextureView of the compositor scene:
let letterbox = LetterboxParams::compute(src_w, src_h, DST_SIZE);
let mut enc = device.create_command_encoder(&Default::default());
pipeline.dispatch(&device, &queue, &mut enc, &scene_view, letterbox);
queue.submit(Some(enc.finish()));

let raw: Vec<f32> = match ort_bridge::extract_web_gpu_buffer(pipeline.output()) {
    Some(gpu_buf) => {
        let dims = js_sys::Array::of4(
            &1.into(), &3.into(), &DST_SIZE.into(), &DST_SIZE.into());
        let js = ort_bridge::ort_run_gpu_buffer(&gpu_buf, dims).await?;
        js_sys::Float32Array::from(js).to_vec()
    }
    None => { /* readback + ort_run_cpu_slice — see extract_web_gpu_buffer docs */
        unimplemented!("wgpu HAL escape hatch unavailable on this wgpu build");
    }
};

let dets = decode_yolo_output(
    &raw, src_w, src_h,
    letterbox.scale, letterbox.pad_x_px(), letterbox.pad_y_px());
let filtered = nms(&dets, 0.45);
```

## Web usage — open_quartz (transition)

```rust
use rimeflow_yolov8n::{
    ort_bridge::{self, get_output_f32, get_f64},
    postprocess::{decode_yolo_output, nms},
    MODEL_URL,
};

ort_bridge::capture_webgpu_device();
ort_bridge::ort_init(MODEL_URL).await?;

// canvas is &web_sys::HtmlCanvasElement
let result = ort_bridge::ort_detect(&canvas).await?;

// Race with the compositor's canvas backing texture: skip this cycle.
if result.is_null() {
    return; // caller advances its own state (Kalman-only, etc.)
}

let raw   = get_output_f32(&result, "output").unwrap();
let scale = get_f64(&result, "scale") as f32;
let pad_x = get_f64(&result, "padX")  as f32;   // already in pixel units
let pad_y = get_f64(&result, "padY")  as f32;
let src_w = get_f64(&result, "srcW")  as u32;
let src_h = get_f64(&result, "srcH")  as u32;

let dets     = decode_yolo_output(&raw, src_w, src_h, scale, pad_x, pad_y);
let filtered = nms(&dets, 0.45);
```

The web page must serve `onnxruntime-web` at `/ort/ort.min.js` and its wasm
artifacts under `/ort/`, and the model at `/models/yolov8n.onnx` (matching
`MODEL_URL`).

## Native usage

`Cargo.toml`:

```toml
[dependencies]
rimeflow-yolov8n = { git = "https://github.com/caozisheng/rimeflow-yolov8n",
                     features = ["native", "native-coreml", "model-embedded"] }
# Platform-specific: pick one of native-coreml / native-directml / native-cuda /
# native-tensorrt / native-nnapi / native-qnn / native-openvino. All optional.
```

```rust
use rimeflow_yolov8n::{
    native_ort::NativeOrtBackend,
    preprocess::{LetterboxParams, PreprocessPipeline},
    postprocess::{decode_yolo_output, nms},
    DST_SIZE, MODEL_BYTES,
};

let pipeline = PreprocessPipeline::new(
    &device, DST_SIZE, PreprocessPipeline::default_buffer_usage());
let mut backend = NativeOrtBackend::new(MODEL_BYTES, &device, &queue, DST_SIZE)?;
println!("YOLOv8n running on {:?}", backend.resolved_ep());

// Per frame:
let letterbox = LetterboxParams::compute(src_w, src_h, DST_SIZE);
let mut enc = device.create_command_encoder(&Default::default());
pipeline.dispatch(&device, &queue, &mut enc, &scene_view, letterbox);
queue.submit(Some(enc.finish()));

let raw = backend.infer_from_wgpu_buffer(pipeline.output(), &device, letterbox)?;
let dets = decode_yolo_output(
    &raw, src_w, src_h,
    letterbox.scale, letterbox.pad_x_px(), letterbox.pad_y_px());
let filtered = nms(&dets, 0.45);
```

`infer_from_wgpu_buffer` currently reads back to host and runs the CPU-visible
tensor through the selected EP; each EP still accelerates inference itself.
Per-EP zero-copy handoffs (DirectML `ID3D12Resource` shared buffer, CoreML
`MTLBuffer.contents()`, CUDA-Vulkan external memory) are follow-up work with
no API change on this side.
